# Aya

[公式サイト](https://m-simplifier.github.io/aya-daw/) · [English](README.md) · [Windows版をダウンロード](https://github.com/M-simplifier/aya-daw/releases/latest/download/Aya-Windows-x64.zip) · [開発者向けガイド](docs/developer-guide.ja.md)

音型を作り、聴きながら変え、時間軸へ並べて一曲にするローカル制作アプリです。音符の生成も音の計算もHaskell/GHCが行います。ブラウザーには編集画面を表示し、音声は別のネイティブプロセスからWindowsの音声デバイスへ送ります。

## 起動と終了

配布フォルダーの **Launch.cmd** をダブルクリックすると、制作画面が開きます。インストールやアカウントは不要です。終了するときはプロジェクトを保存し、**Close.cmd** をダブルクリックしてください。画面だけを閉じた場合は、再びLaunch.cmdで同じアプリへ戻れます。

初回はオリジナル制作例「硝子の潮 — Glass Tides」を表示します。19平均律、リズム、低音、和音、旋律、オートメーションを使った40小節の曲です。「再生」で聴けます。音量を小さくしてから始めてください。

## 空の曲から作る

1. 「新規」で空の曲にします。トラックを追加し、右側で音色を選びます。
2. 音型を作り、音型編集で音符を置きます。音符は移動・長さ・音高・強さを変更できます。規則を使う場合はユークリッド、アルペジオ、和音進行を選び、表示された音符を聴きながら調整します。
3. 音型を時間軸へ配置します。クリップを伸ばすと音型が繰り返されます。同じ音型を使うクリップは編集結果を共有します。別の展開へ直すときは複製して独立させます。
4. 回転・逆行・移調・反転・伸縮・確率で展開を作ります。「音符に確定」を押すと生成結果を直接編集できます。元に戻す・やり直すも使えます。
5. トラックの音量・定位・音色とディレイを調整します。音量・定位・カットオフはオートメーションで時間変化を描けます。ミュート・ソロ、区間ループで確認します。
6. 「保存」で素材を含む `.aya` をダウンロードします。中身はJSONです。「開く」でそのファイルを選ぶと編集を再開できます。付属の `.aya.json` 制作例も開けます。WAVをサンプル音色へ読み込んだ場合も元のWAVがファイル内に含まれます。別途、自動回復をアプリの `.work` 内へ保存します。
7. 「書き出す」を開き、「WAVを書き出す」を押すと全曲のWAVを作ります。「トラックごとのWAVも書き出す」を選ぶとステムも作ります。結果に表示された各ファイルをダウンロードしてください。48 kHzステレオで、曲末のリリースとディレイを含めます。書出し中もネイティブ再生は別プロセスで続きます。

鍵盤入力を有効にするとPCキーで演奏できます。録音は押下・離鍵の時刻と順序を残して音符へ変換します。再生中の発音は次の音声ブロックへ届きます。機器やブラウザーを含む入力遅延がゼロになるという意味ではありません。パニック操作は演奏中の音を止めます。

## 音階と素材

音高はMIDIの半音単位を基準にした連続値です。60.5は60と61の中間です。平均律の分割数と音階は生成規則へ使い、12音へ丸めません。音階の値は、その平均律のステップです。たとえば19平均律の `[0,3,5,8,11,13,16]` は7音の音階です。基準周波数はA4の周波数です。「新しい音型の中心音高」を変えると、次に作る音型の基準になります。

WAVはモノラルまたはステレオのPCM 8/16/24/32 bitと浮動小数32/64 bitを読み込めます。圧縮WAV、MP3、AIFFは読み込めません。ファイル構造、サイズ、有限値と素材情報を確認してから採用します。素材は合計32個、復号したFloat値で96 MiBまでです。

## MIDIとの往復

SMF type 0/1のPPQN形式を読み込み、type 0・960 PPQNで書き出します。音符、ベロシティ、発音開始時のピッチベンドとRPNのベンド幅、サステイン、テンポを読み込みます。テンポ変更は発音の実時間を保持するように一定テンポの拍位置へ展開します。発音途中の連続ベンドは開始時の音高へ固定し、その場合は警告します。

書出しは音ごとにチャンネルを割り当て、±2半音のピッチベンドで微分音を渡します。旋律声は同時15声までです。超える場合は書出しを拒否します。受信側にはRPNとピッチベンドへの対応が必要です。音色はGM近似で、Ayaの音作り・素材・ミックス・エフェクトはMIDIでは再現されません。音をそのまま渡すときはWAVかステムを使ってください。SMPTE時刻、SMF type 2、プラグイン、外部MIDI機器の自動接続は初版の対象外です。

## 実装と検査

通常のGHC 9.14.1とCabal 3.18.2.0をPATHへ追加し、`cabal update` のあと `scripts/build.ps1 -Tests` でローカル開発用に組み立てます。Node 24が画面・サイトの検査、Python 3.10以上が依存物の通知収集に必要です。配布版を使う人にはビルド環境は不要です。

公開・再配布用には `scripts/build.ps1 -Release -Tests`、続いて `scripts/package.ps1 -SkipBuild` を使ってください。通常のGHCのローカルビルドにはGMPが静的に含まれる場合があります。配布用の手順では、検証した交換可能なGMP DLLと完全な対応ソース・通知を同梱し、インストール済みコンパイラーは変更しません。

`scripts/integration-test.mjs` は別のローカル起動で、新規作成から保存・再読込み・ステムまで通す検査です。音声の独立参照、実デバイス試験と計測範囲は `docs/audio-*.md` を参照してください。

音楽コンパイラーの各段は次の意味を持ちます。

| 段 | 入力から何を決めるか | 保持するもの |
|---|---|---|
| 読込み・検査 | 外部JSONを時刻・ID・曲の値へ読み、参照・範囲・容量を検査 | 不正な曲は現在の音へ反映しない |
| 生成 | 規則を具体的な音符区間へ展開。和音は有限の候補と声部ごとの移動費用から全進行を選ぶ | 同じ規則・音階・seedの結果、各声の音符ID |
| 変形 | 逆行は区間全体を反射。回転は境界をまたぐ区間を分割。伸縮は周期と音符を同時に変える | 有理数の区間と指定された音高操作 |
| 配置 | 音型をクリップ内で反復し、最後の区間だけクリップ端で切る | トラック・クリップ・反復ごとのIDと正確な拍位置 |
| 音声計画 | 拍の境界を48 kHzの整数サンプル位置へ一度だけ丸め、Hz・音量・オートメーションを渡す | 画面・再生・WAVが同じ解決済み音符を使う |

浮動小数の演算順を変える最適化を、ビット単位の同値とは扱いません。拍の変形は有理数ですが、JSONの数値表示、Hz変換、音声演算は有限精度です。保存時の表示小数から任意の有理数を厳密に復元する保証はありません。標準の編集・再読込み例はサンプル位置とWAVの一致を検査します。MIDIの拍と14 bitベンドには別の量子化誤差があります。

学んだ先例は、[Euterpeaの音楽合成](https://github.com/Euterpea/Euterpea/blob/master/HSoM/Music.lhs)、[Tidalの有理時間とパターン](https://github.com/tidalcycles/Tidal)、[声部進行の幾何](https://collaborate.princeton.edu/en/publications/the-geometry-of-musical-chords/)、[MIDI AssociationのSMF仕様](https://midi.org/standard-midi-files)です。ソースをそのまま組み込んだものではありません。ブラウザーの音声合成や事前生成した音源の再生へ置き換えず、GHCの実行器がサンプルを計算します。

曲は最大32トラック・256音型・2,048クリップ・配置後32,768音です。音声側はリリースを含む同時256声です。上限や検査に反する曲は理由を表示して拒否します。これは特定のPCと機器で検査した初版であり、録音スタジオ向け全機能や、あらゆる負荷での無欠落を保証するものではありません。
